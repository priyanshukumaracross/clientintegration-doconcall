Client API Integration Guide

Send us your customers’ Global Doctor On Call enrolments from your own system, check their status at any time, and sign your customers straight in to the app. Each enrolment gets its policy number as soon as we receive it; we verify the details and activate it.

Version 2.0 · 20 November 2026

Environment
The Production URL will be shared with you before go-live. The examples show a placeholder until then.

Overview

All over HTTPS with JSON.

YouGet a tokenExchange your Client ID and Secret for a 1-hour access token.
YouSend enrolmentsUp to 500 customers per call. Each gets its policy number in the response.
WeVerify & activateWe check the details and activate the subscription. The customer is emailed their app link.
YouSign customers inSend a customer straight in to the app from your own portal — no login code needed.

You can also check each record’s status at any time.

1Credentials

We give you a Client ID (starts with gdoc_) and a Client Secret for each environment.

Keep the secret on your server. Never put it in a mobile app, a web page, a URL or a log. If it leaks, ask us for a new one; the old secret stops working immediately.

2Get an access token

Request
POST {BASE_URL}/client-api/token
Content-Type: application/json

{ "clientId": "gdoc_…", "clientSecret": "…", "policyNumber": "AADOC000123" }

client_id / client_secret are accepted too, or HTTP Basic authentication (-u clientId:clientSecret).

policyNumber is optional. Leave it out for a normal token. Send it only when you are about to sign that customer in: the token is then tied to that policy, valid for 15 minutes, and the response also contains "policy_number". A policy-bound token works for every other API as well. The policy must be one of yours (otherwise 404 Policy not found).

Response · 200
{
  "success": true,
  "message": "Token issued",
  "data": { "access_token": "eyJ…", "token_type": "Bearer", "expires_in": 3600 }
}

The token is valid for 1 hour. Send it on every other call as Authorization: Bearer <access_token>. Reuse it until it expires, then get a new one (you’ll get 401).

StatusMeaning
401 Invalid client credentialsWrong ID or secret, or your access has been switched off.
429Too many wrong attempts — wait 15 minutes.

3Send enrolments

Request
POST {BASE_URL}/client-api/sales
Authorization: Bearer <access_token>
Content-Type: application/json

Fields

FieldRequiredNotes
gwfNumber✔GWF No (Visa Application Reference Number) — the record’s key. Spaces are ignored and it isn’t case-sensitive. Max 50 characters.
fullName✔Max 100 characters.
email✔The customer signs in to the app with this email.
mobileNumber✔*A 10-digit Indian mobile (9876543210, +91 98765 43210 and 098765 43210 all work), or an international number starting with +. *Required when your account is set up that way (we’ll tell you) — records without one are then rejected.
countryOfVisaApplicationCenterMax 100 characters.
estimatedDateOfTravelYYYY-MM-DD or DD/MM/YYYY.
subscriptionStartDateFirst day of cover. YYYY-MM-DD or DD/MM/YYYY. Send together with subscriptionEndDate: once we’ve verified the record, these become its activation date and validity. Without them, we set the activation date (30 days of cover).
subscriptionEndDateLast day of cover (inclusive). On or after the start date, at most about a year later.
dateOfBirthYYYY-MM-DD or DD/MM/YYYY, in the past.
genderMale, Female or Other (also M / F / O). With dateOfBirth, the customer’s profile is complete — they are not asked for these details in the app.
paymentDateTimeWhen the customer paid you, e.g. 2026-11-20T14:30:00+05:30. A time without a zone is read as India time.

Body formats. Send one record, an array of records, or { "records": [ … ] } — up to 500 records per call (1 MB). Field names are matched without regard to case, and gwfNo, name, emailAddress, mobile, country, travelDate, startDate, endDate, dob and paymentDate are accepted as alternatives.

Body
{
  "records": [
    {
      "gwfNumber": "GWF012345678",
      "fullName": "Asha Rao",
      "email": "asha.rao@example.com",
      "mobileNumber": "9876543210",
      "countryOfVisaApplicationCenter": "India",
      "estimatedDateOfTravel": "2026-12-20",
      "subscriptionStartDate": "2026-12-01",
      "subscriptionEndDate": "2026-12-30",
      "dateOfBirth": "1990-02-01",
      "gender": "Female",
      "paymentDateTime": "2026-11-20T14:30:00+05:30"
    },
    { "gwfNumber": "GWF012345679", "fullName": "Ravi Kumar", "email": "ravi.k@example.com", "mobileNumber": "9812345678" }
  ]
}

Sending the same gwfNumber again replaces its details, as long as we haven’t activated it yet. After activation, changes go through our support team.

Response

One result per record, in the order sent:

Response · 200
{
  "success": true,
  "message": "Some records were rejected",
  "data": {
    "received": 3, "created": 1, "updated": 1, "rejected": 1,
    "results": [
      { "index": 0, "gwfNumber": "GWF012345678", "status": "created", "policyNumber": "AADOC000123" },
      { "index": 1, "gwfNumber": "GWF012345679", "status": "updated", "policyNumber": "AADOC000124" },
      { "index": 2, "gwfNumber": "GWF012345680", "status": "rejected", "errors": ["email is required"] }
    ]
  }
}

Every saved record returns its policyNumber straight away — keep it: it’s the customer’s policy number once activated, and you need it to sign the customer in. Sending the same GWF No again keeps the same number.

Always check rejected and results. A rejected record wasn’t saved — fix it and send it again. The other records in the same call were saved.

Rejection reasons you may see:

  • This GWF No is already activated — contact support to change it
  • This GWF No has already been registered by another source, or This GWF No is already registered with us
  • Duplicate of record N in this call
  • Field problems, such as fullName is required, mobileNumber is required, mobileNumber: … or subscriptionEndDate must be on or after subscriptionStartDate

5Sign a customer in to the app

When a customer who is signed in on your portal wants to use Global Doctor On Call, send them straight in to the app — they don’t enter a login code.

You · serverPolicy tokenPOST /client-api/token with your credentials and the customer’s policyNumber.
You · serverAuthenticatePOST /client-api/customer-auth with the customer’s details. You get a redirectUrl.
Customer’s browserRedirectSend the customer to redirectUrl. The app opens, already signed in.
Request
POST {BASE_URL}/client-api/customer-auth
Authorization: Bearer <token issued for this policyNumber>
Content-Type: application/json

{
  "gwfNumber": "GWF012345678",
  "policyNumber": "AADOC000123",
  "fullName": "Asha Rao",
  "email": "asha.rao@example.com",
  "mobileNumber": "9876543210"
}
FieldRequiredChecked against the policy
gwfNumber✔Must be this policy’s GWF No (spaces and case ignored).
policyNumber✔Must be the policy the token was issued for, and activated.
fullName✔Must match the name you sent (case, spacing and punctuation ignored).
emailone or bothMust match the policy’s email.
mobileNumberMust match the policy’s mobile number (any of the formats above).
Response · 200
{
  "success": true,
  "message": "Customer authenticated — redirect them to redirectUrl",
  "data": {
    "redirectUrl": "https://<your-app>/sso#code=eyJhbGciOiJIUzI1NiIs…",
    "expiresIn": 300,
    "policyNumber": "AADOC000123"
  }
}
Redirect the customer within 5 minutes. The link signs in exactly one browser, once. It carries a signed, single-use token after #, which browsers never send to any server, and the app exchanges it for the customer’s session (JWT access and refresh tokens). Call this API again for a new link whenever the customer comes back.
StatusWhen
401The token is missing or expired, or wasn’t issued for a policy (get one with policyNumber).
403The token was issued for a different policy, or the policy has been deactivated.
404Policy not found (not one of yours).
409The policy hasn’t been activated yet, or your customer app isn’t set up yet.
422The details don’t match the policy — the message names the fields, e.g. The customer details don't match this policy: email.

The customer can always sign in to the app with a login code to their email instead.

Errors and retries

StatusWhenWhat to do
200The call was processed (some records may be rejected).Check rejected and results.
422Every record in the call was rejected.Fix the records listed in results and resend.
400The body is empty or not JSON.Check the request body.
413More than 500 records, or over 1 MB.Split into smaller calls.
401The token is missing, expired or invalid.Get a new token and retry.
429Too many requests.Wait, then retry.
5xx or no responseA temporary problem.Retry with a delay. Sending a record twice is safe.

Every response has the same shape: success, message, and data (plus meta on lists).

Get a token, send customers, list the ones still pending — and (curl) sign a customer in.

BASE={BASE_URL}

TOKEN=$(curl -s -X POST $BASE/client-api/token \

curl -X POST $BASE/client-api/sales \

// Node.js 18+ (built-in fetch)
const BASE = '{BASE_URL}';

async function getToken() {
  const res = await fetch(`${BASE}/client-api/token`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ clientId: process.env.GDOC_CLIENT_ID, clientSecret: process.env.GDOC_CLIENT_SECRET }),
  });
  if (!res.ok) throw new Error(`Token request failed: ${res.status}`);
  return (await res.json()).data.access_token;
}

async function sendEnrolments(records) {
  const token = await getToken();
  const res = await fetch(`${BASE}/client-api/sales`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ records }),
  });
  const body = await res.json();
  for (const r of body.data?.results ?? []) {
    if (r.status === 'rejected') console.warn(r.gwfNumber, r.errors.join('; '));
  }
  return body.data;
}

sendEnrolments([
  { gwfNumber: 'GWF012345678', fullName: 'Asha Rao', email: 'asha.rao@example.com', mobileNumber: '9876543210' },
]).then(console.log);
# Python 3 with requests (pip install requests)
import os, requests

BASE = "{BASE_URL}"

def get_token():
    r = requests.post(f"{BASE}/client-api/token", json={
        "clientId": os.environ["GDOC_CLIENT_ID"],
        "clientSecret": os.environ["GDOC_CLIENT_SECRET"],
    }, timeout=30)
    r.raise_for_status()
    return r.json()["data"]["access_token"]

def send_enrolments(records):
    token = get_token()
    r = requests.post(f"{BASE}/client-api/sales", json={"records": records},
                      headers={"Authorization": f"Bearer {token}"}, timeout=60)
    data = r.json()["data"]
    for res in data["results"]:
        if res["status"] == "rejected":
            print(res["gwfNumber"], "; ".join(res["errors"]))
    return data

print(send_enrolments([
    {"gwfNumber": "GWF012345678", "fullName": "Asha Rao", "email": "asha.rao@example.com", "mobileNumber": "9876543210"},
]))

What happens next

  1. Your records appear in our admin panel under your company’s name, each with the policy number you received.
  2. We verify the details and activate each record. With subscriptionStartDate and subscriptionEndDate, those are its activation date and validity; without them, we set the activation date and the service runs for 30 days. The customer then gets an email with the link to the app.
  3. GET /client-api/sales shows the record as ACTIVATED, with its activation date and validity. From then on you can sign the customer in.
  4. If you sent dateOfBirth and gender, the customer goes straight to the app’s home screen; otherwise the app asks for them once.

Go-live checklist

  • Token, send and status calls all work on UAT, including a rejected record (for example, one without an email).
  • Your system reads results, stores each policyNumber, and handles rejected records.
  • Customer sign-in works on UAT: policy token → /client-api/customer-auth → redirect, including a refused case (for example, a wrong name).
  • Expired tokens (401) are renewed automatically, and 5xx errors are retried.
  • The Client Secret is stored only on your server (environment variable or secrets manager).
  • You have received your Production Client ID, Secret and base URL, and switched all three together.
